## 1. 데이터 이해: kr\_lung\_cancer

사용 데이터는 국립암센터가 공개한 폐암 합성데이터이고, 실제 환자 기록이 아닙니다. 환자 기본정보 한 장에 나머지 네 테이블이 `pt_sbst_no`(환자대체번호) 하나로 붙습니다.

### 1-1. 테이블 지도

| 테이블 | 한 행의 의미 | 행 수 | 환자 1명당 행 수 |
| --- | --- | --- | --- |
| `lung_pt_bsnf` | 환자 한 명(기본정보) | 9,897 | 1행 |
| `lung_oprt_nfrm` | 수술 한 번 | 3,463 | 0행 또는 여러 행 |
| `lung_trtm_casb` | 항암제 치료 한 차수 | 36,567 | 0행 또는 여러 행 |
| `lung_trtm_rd` | 방사선 치료 한 번 | 4,312 | 0행 또는 여러 행 |
| `lung_dead_nfrm` | 사망 기록 | 3,959 | 0행 또는 1행 |

JOIN 전에 "한 행이 무엇을 뜻하는가"를 먼저 파악합니다. 환자당 1행인 테이블과 여러 행인 테이블을 붙일 때 결과가 달라지기 때문입니다.

### 1-2. 주요 열

| 열 | 뜻 |
| --- | --- |
| `bspt_frst_diag_ymd` | 최초진단일자 (코호트 기준일로 사용) |

| `bspt_idgn_age` | 진단 시 나이 |

| `bspt_dead_ymd`, `dead_ymd` | 사망일자 (환자 테이블 / 사망 테이블) |

### 1-3. NULL의 의미

환자 한 행에서 NULL은 "그 일이 없었다" 또는 "기록이 없다"는 뜻이고, 0이 아닙니다. 첫 수술일이 NULL이면 수술 기록이 없다는 뜻이며, 6교시에서 "치료를 받았는가"를 이 값으로 판단합니다.

### 1-4. 합성데이터 주의

결과 숫자를 "실제 병원의 사망률이나 치료 성적"이라고 말하면 안 됩니다. 원본 그대로 둔 이상한 점은 다음과 같습니다.

- 성별이 전부 `M`이라 성별 비교가 불가능합니다.
- 전체생존기간일수가 음수입니다 (예: -2042, 직접 계산하면 2042). 저장된 열보다 날짜에서 직접 계산한 값을 씁니다.
- 병기에 `x`가 섞여 있습니다.
- 마지막 방문일이 사망 기록 마감(2021-07-31)보다 뒤인 환자가 267명이고, 최대 2027-05-22입니다. 코호트 안에서는 138명이 "1년 생존 확인"으로 분류됩니다.
- 날짜 범위는 진단일 2008-01-04 \~ 2020-10-20, 사망 기록 \~ 2021-07-31입니다.

### 1-5. 낱말 풀이

| 낱말 | 뜻 |
| --- | --- |
| 병기 | 암이 퍼진 정도. 0기에서 4기로 갈수록 많이 퍼진 상태 |
| 보조항암(Adjuvant) | 수술 뒤에 하는 항암치료 |
| 다학제 진료팀 | 여러 진료과 의사가 함께 치료 방침을 정하는 팀 |
| RWE | 실사용 근거. 임상시험이 아니라 실제 진료 기록을 분석해 얻은 근거 |
| 코호트 | 같은 조건으로 묶어 일정 기간 지켜보는 환자 집단 |

## 2. 5교시 개념: 코호트와 사망률

5교시의 핵심은 "누구를 분모에 둘지"를 CTE로 정의하고, LEFT JOIN으로 사건(사망)을 붙여 비율을 내는 것입니다.

### 2-1. CTE (WITH 이름 AS)

CTE는 긴 쿼리를 한 번에 쓰지 않고 중간 결과에 이름을 붙여 단계로 나누는 방법입니다. 요리 재료를 먼저 손질해 그릇에 담아 두고, 그 그릇에서 꺼내 쓰는 것과 같습니다.

```sql
WITH cohort AS (
  SELECT pt_sbst_no,
         bspt_frst_diag_ymd AS index_dd,
         YEAR(bspt_frst_diag_ymd) AS diag_year
  FROM lung_pt_bsnf
  WHERE bspt_frst_diag_ymd >= '2010-01-01' AND bspt_frst_diag_ymd < '2020-01-01'
)
SELECT * FROM cohort LIMIT 5;
```

- 괄호 안 SELECT가 먼저 실행되어 `cohort`라는 임시 결과표가 생기고, 아래 SELECT가 그 표를 테이블처럼 씁니다.
- 영구 저장이 아니라 그 쿼리가 끝나면 사라집니다.
- 여러 개는 쉼표로 잇고, `WITH`는 맨 앞에 한 번만 씁니다.
- 자주 막히는 곳: 괄호 짝, `AS`의 위치, CTE 사이 쉼표 빠뜨리기, 두 번째 CTE 앞에 `WITH` 또 쓰기.

### 2-2. 코호트의 세 요소

"1년 사망률"이라는 말에는 누구를, 언제부터, 무엇을 셀지가 빠져 있고, 셋을 정해야 숫자가 나옵니다.

| 요소 | 이번 정의 |
| --- | --- |
| 누구를 | 2010\~2019년 진단 환자 8,436명 |
| 기준일 | 최초진단일자 |
| 추적 기간 | 기준일부터 365일 |
| 사건 | 사망 |

- 2020년 진단자를 뺀 이유: 1년을 다 지켜보지 못했을 수 있어서입니다.
- 2008\~2009년 진단자(827명)를 뺀 이유: 뺄 이유가 있어서가 아니라 표를 10개 연도로 끊으려고 뺐습니다.
- 코호트 범위는 분석하는 사람이 정하고, 정한 범위를 결과와 함께 적습니다.
- 채용 공고의 "SQL 기반 코호트 구축"이 바로 이 일입니다.

### 2-3. LEFT JOIN: 사건이 없는 사람도 남기기

사망 테이블에는 사망한 사람만 있어서, `JOIN`으로 이으면 사망 기록이 없는 환자가 사라집니다. 반 출석부에 시험 제출자 명단을 붙일 때 제출 안 한 학생을 지우면 제출률이 틀어지는 것과 같습니다.

| 종류 | 동작 |
| --- | --- |
| `JOIN` (INNER) | 양쪽에 다 있는 행만 남김. 사망 기록 없는 환자가 사라짐 |
| `LEFT JOIN` | 왼쪽 행은 전부 남기고, 오른쪽에 짝이 없으면 NULL |

| pt\_sbst\_no | dead\_ymd |
| --- | --- |
| RN000000005 | 2013-09-07 |
| RN000000010 | NULL |

사건이 없는 사람도 분모에 남아야 비율이 맞습니다.

### 2-4. 단계 나누기: cohort, outcome, 집계

| 단계 | 내용 | 행 수 |
| --- | --- | --- |
| cohort | 누구를, 기준일 | 8,436행 |
| outcome | 환자별 1년 안 사망 여부 (0/1) | 8,436행 |
| 집계 | 진단 연도별 | 10행 |

단계마다 행 수가 얼마여야 하는지 미리 알고, 실행할 때마다 확인합니다. cohort와 outcome은 환자당 1행이라 행 수가 같고, 집계에서 줄어듭니다.

### 2-5. 1년 안 사망 여부를 0/1로 만들기

```sql
CASE WHEN d.dead_ymd <= c.index_dd + INTERVAL 365 DAY THEN 1 ELSE 0 END AS dead_1y
```

- `+ INTERVAL 365 DAY`는 날짜에 365일을 더합니다.
- 조건이 맞으면 1, 아니면 0이고, 0/1 열의 평균이 비율입니다.
- `dead_ymd`가 NULL이면 조건이 참이 아니어서 0이 됩니다. 편리하지만 2-8의 함정이 여기서 시작됩니다.

### 2-6. 일부러 틀려 보기: JOIN으로 바꾸면

LEFT JOIN을 JOIN으로 바꾸면 에러 없이 숫자만 달라집니다. 사망 기록 없는 환자가 통째로 빠져 분모가 줄고, 사망률이 1.5\~2배로 올라갑니다.

| diag\_year | JOIN 결과 patients | JOIN 결과 사망률(%) | LEFT JOIN(정답) patients | LEFT JOIN(정답) 사망률(%) |
| --- | --- | --- | --- | --- |
| 2010 | 308 | 48.4 | 474 | 31.4 |
| 2011 | 386 | 46.4 | 661 | 27.1 |
| 2012 | 423 | 48.5 | 784 | 26.1 |

코호트는 8,436명인데 결과의 환자 수 합이 3,293이면 중간에 사람이 사라진 것입니다. 찾는 방법은 단계마다 행 수를 세는 것 하나입니다.

### 2-7. 행이 늘어나는 경우 (fan-out)

오른쪽 테이블이 환자당 여러 행(예: 수술 여러 번)이면 LEFT JOIN 뒤 행 수가 오히려 늘어나서, 코호트 8,436행이 8,527행이 되는 식입니다. 이대로 세면 환자 수가 틀립니다.

- 해결: 붙이기 전에 CTE에서 `GROUP BY`로 환자당 1행(예: `MIN(수술일)`)으로 줄인 뒤 LEFT JOIN합니다.
- 줄인 뒤 `AVG`는 NULL을 빼고 계산하므로, 수술 안 받은 사람은 평균에서 제외됩니다.

| 위험 | 원인 | 결과 |
| --- | --- | --- |
| 행이 줄어듦 | `JOIN`을 써서 짝 없는 행 제거 | 분모 감소 |
| 행이 늘어남 | 오른쪽이 환자당 여러 행 | 환자 중복 집계 |

둘 다 행 수 확인으로 잡습니다.

### 2-8. 중도절단 (censoring)

중도절단은 지켜보는 기간을 다 채우기 전에 소식이 끊긴 상태입니다. 사망도 생존도 아니고, "그날까지는 살아 있었다는 것만 안다"는 뜻입니다.

- 생기는 경우: 다른 병원으로 옮김, 더 오지 않음, 자료를 뽑은 날에 아직 지켜보는 중.
- 예시: RN000000010은 진단 7일 뒤 수술받고 이후 방문 기록이 없습니다. 1년 안 사망 여부를 알 수 없는데 쿼리는 이 사람을 "사망 안 함(0)"으로 셉니다.

1년 시점에서 코호트 8,436명을 세 상태로 나눈 결과입니다.

| 상태 | 기준 | 인원 |
| --- | --- | --- |
| 사망 | 365일 안에 사망 기록 있음 | 1,676 |
| 1년 생존 확인 | 365일 뒤 사망했거나, 사망 기록 없이 365일 뒤에도 방문 기록 있음 | 2,662 |
| 중도절단 | 사망 기록 없고 마지막 방문일이 365일 전이거나 비어 있음 | 4,098 (48.6%) |

CASE는 위에서부터 처음 맞는 조건에서 멈추므로 순서가 중요합니다. 첫 조건(1년 안 사망)에서 이미 걸러졌기 때문에, 그 아래로 내려온 사망 기록은 전부 1년 뒤 사망입니다. 마지막 방문일이 NULL이면 비교가 참이 아니어서 마지막 `ELSE`(중도절단)로 갑니다.

### 2-9. 이 표를 생존율로 읽으면 안 되는 이유

진단 연도가 늦을수록 1년 안 사망률이 낮아지지만(2010년 31.4%, 2019년 11.2%), "치료가 좋아져서"라고 말할 수 없습니다.

- 중도절단 비율이 2010년 28.7%에서 2019년 68.5%로 올라갑니다. 쿼리는 이들을 전부 "사망 안 함"으로 세므로 최근 연도일수록 사망률이 낮게 나옵니다.
- 원본 설명서에 사망일자의 출처가 없어서, 병원이 아는 사망만 있다면 병원 밖 사망은 빠집니다.
- 합성데이터입니다.
- 중도절단을 표에서 통째로 빼고 계산해도 틀립니다. 그 사람이 살아 있던 기간의 정보까지 버리기 때문입니다.
- Kaplan-Meier로 다시 세면 전체 1년 사망률이 19.9%에서 36.3%로 올라갑니다 (2010년 12.0%p, 2019년 18.0%p 차이). 중도절단된 사람은 그때까지만 분모에 넣는 방식이며, 계산 자체는 이 과정의 범위 밖이고 R, Python 같은 통계 도구가 합니다.

오늘 가져갈 것은 분모에 누가 들어 있는지, 사건을 놓친 사람이 있는지부터 묻는 습관입니다.

### 2-10. SQL 담당의 일: 생존분석용 데이터셋 만들기

SQL 담당은 환자마다 "지켜본 날"과 "사건 여부" 두 열을 만들어 통계 도구에 넘깁니다.

```sql
DATEDIFF(COALESCE(d.dead_ymd, c.last_vst), c.index_dd) AS follow_days,
CASE WHEN d.dead_ymd IS NOT NULL THEN 1 ELSE 0 END AS event
```

| 함수 | 뜻 |
| --- | --- |
| `COALESCE(a, b)` | a가 NULL이면 b를 씀. 사망일이 있으면 사망일, 없으면 마지막 방문일 |
| `DATEDIFF(끝, 시작)` | 두 날짜 사이의 일수 |

RN000000010의 첫 행은 `follow_days = 7`, `event = 0`입니다.

### 2-11. 워밍업: 값부터 세어 보기

분석 전에 열마다 값이 어떻게 들어 있는지 `GROUP BY ... COUNT(*)`로 확인합니다. 성별은 `M` 한 줄만 나와 성별 비교가 불가능하고, `MIN`/`MAX`로 날짜 범위를 확인해 진단일·사망일 범위를 파악합니다.

## 3. 6교시 개념: CASE와 조건부 집계

6교시의 핵심은 CASE로 값을 현장의 구분으로 묶고, 0/1 평균으로 여러 비율을 한 쿼리에 내는 것입니다.

### 3-1. 값부터 세어 보기

| bspt\_stag\_vl | 환자 수 |
| --- | --- |
| 0 | 13 |
| 1 | 3,129 |
| 2 | 671 |
| 3 | 1,564 |
| 4 | 4,170 |
| x | 350 |

숫자처럼 보이지만 `x`가 섞여 있어 문자 열입니다. 0기는 13명뿐이라 6가지를 그대로 쓰면 표가 길고 읽기 어려워서, 현장의 구분(초기 / 국소 진행 / 전이)으로 묶습니다.

### 3-2. CASE의 틀

```sql
CASE WHEN bspt_stag_vl IN ('0','1','2') THEN '초기'
     WHEN bspt_stag_vl = '3' THEN '국소 진행'
     WHEN bspt_stag_vl = '4' THEN '전이'
     ELSE '병기 미상'
END AS stage_group
```

- 위에서부터 처음 맞는 조건에서 멈춥니다.
- `ELSE`가 없으면 NULL이 됩니다.
- `END` 뒤에 열 이름(별칭)을 붙입니다.
- 원본 테이블은 바뀌지 않고 결과에만 새 열이 생깁니다.
- 이름 앞에 `1)`, `2)`를 붙이는 것은 정렬 순서를 맞추려는 것입니다.

| bspt\_stag\_vl (원래 값) | stage\_group (새 열) |
| --- | --- |
| 1 | 초기 |
| 3 | 국소 진행 |
| x | 병기 미상 |

### 3-3. 만든 열로 GROUP BY

CASE로 6가지 값을 4그룹으로 만들고 `GROUP BY stage_group`을 하면 4행이 나옵니다. 3교시의 GROUP BY와 같고, 묶는 기준이 방금 만든 열일 뿐입니다. MySQL은 SELECT에서 만든 별칭을 GROUP BY에 쓸 수 있지만 다른 DB에서는 안 될 수 있습니다.

### 3-4. 조건부 집계

```sql
AVG(CASE WHEN bspt_frst_oprt_ymd IS NOT NULL THEN 1 ELSE 0 END) * 100
```

수술일이 있으면 1, 없으면 0으로 만들고, 그 평균에 100을 곱하면 수술받은 비율(%)입니다.

| 환자 | 수술 여부 |
| --- | --- |
| A | 1 |
| B | 0 |
| C | 0 |
| D | 1 |

(1+0+0+1) ÷ 4 = 0.5, 즉 50%입니다.

- 전체 환자의 수술 비율은 33.9%입니다 (9,897명 중 3,358명).
- 수술, 항암, 방사선, 사망 비율을 쿼리 한 번에 한 표로 낼 수 있고, 비율 열마다 CASE를 하나씩 쓰고 별칭을 각각 다르게 붙입니다.
- 결과 표의 모양: `stage_group`, `patients`, `surgery_pct`, `chemo_pct`, `radiation_pct`, `dead_pct`, 행은 4그룹.

### 3-5. IS NULL / IS NOT NULL

| 조건 | 뜻 |
| --- | --- |
| `bspt_frst_oprt_ymd IS NOT NULL` | 수술 기록 있음 |
| `bspt_dead_ymd IS NULL` | 사망 기록 없음 |

`= NULL`은 쓰면 안 됩니다. NULL과의 비교는 참도 거짓도 아닌 NULL이어서 `WHERE`나 `CASE`에서 참으로 처리되지 않습니다. 날짜가 비었는지로 "그 치료를 받았는가"를 판단합니다.

### 3-6. CASE 안의 OR / AND와 NULL

날짜가 NULL이면 `<=` 비교 결과는 참도 거짓도 아닌 NULL입니다.

- `OR`로 이으면 하나라도 참일 때 참이고, 모두 참이 아니면 `ELSE`로 갑니다.
- "기록이 하나도 없음"은 `AND`와 `IS NULL`로 묻습니다.

### 3-7. 일부러 틀려 보기: 문자를 숫자와 비교하면

문자 열을 숫자와 비교하면(`bspt_stag_vl <= 2`) 에러 없이 경고만 뜨고 그룹이 섞입니다.

| 항목 | 결과 |
| --- | --- |
| 에러 | 없음 (경고만) |
| 행 수 | 4행이 아니라 3행 |
| 초기 그룹 | 3,813이 아니라 4,163 |
| 병기 미상 | 사라짐 |

- 원인: MySQL이 `'x'`를 숫자 0으로 바꿔 비교했고, 0은 2 이하라서 병기 미상 350명이 초기로 들어갔습니다.
- 경고 메시지: `Warning 1292 Truncated incorrect DOUBLE value: 'x'`
- `SHOW WARNINGS`는 바로 앞 쿼리의 경고를 보는 문장입니다. 두 문장을 이어서 실행해야 해서 DBeaver에서는 스크립트 실행(Alt+X)으로 돌립니다.
- 올바른 방식: 문자 열은 문자로 비교합니다. `IN ('0','1','2')`
- 환자 수 합이 9,897로 맞아도 이 실수는 못 잡습니다. 그룹 수(4행)와 값별 인원을 같이 봐야 합니다.

### 3-8. 분모가 다름에 주의

| 구분 | 분모 |
| --- | --- |
| 6교시 실습 (병기 그룹 치료 비율) | 전체 환자 9,897명 |
| 5교시 연계 (병기 그룹 1년 상태) | 코호트 8,436명 (2010\~2019 진단) |

같은 "초기"라도 인원이 다르므로(3,813명 vs 3,358명) 어떤 분모인지 항상 확인합니다.

### 3-9. 5교시와 6교시를 합칠 때

한 쿼리에서 CTE + LEFT JOIN + CASE(병기 그룹) + CASE(1년 상태) + 조건부 집계를 모두 씁니다. 병기별 중도절단 비율을 보면 초기 환자의 약 79%가 중도절단이고, 수술 뒤 이 병원에 더 오지 않은 사람이 많다는 뜻입니다. 그래서 초기의 낮은 1년 사망률(2.6%)은 더 조심해서 읽고, 병기끼리 비교할 때도 중도절단 비율을 같이 봅니다.

## 4. 쿼리 실행 순서와 중간 결과 변화

SQL은 쓰는 순서와 실행되는 순서가 다르고, 단계마다 데이터가 이렇게 바뀝니다.

1. **WITH**: CTE가 먼저 계산되어 임시 표(`cohort` 등)가 만들어집니다.
2. **FROM / LEFT JOIN**: 표를 붙입니다. 왼쪽은 전부 유지하고, 짝이 없으면 NULL로 채웁니다.
3. **WHERE**: 조건에 안 맞는 행을 제거합니다. 코호트 범위를 지정하는 곳입니다.
4. **GROUP BY**: 같은 값끼리 묶습니다.
5. **HAVING**: 묶인 그룹을 조건으로 거릅니다.
6. **SELECT**: CASE로 새 열을 계산하고 AVG, COUNT 같은 집계를 냅니다.
7. **ORDER BY**: 정렬합니다.

CASE는 SELECT 단계에서 계산되는데, MySQL은 그 별칭을 `GROUP BY`에서 쓰게 허용합니다.

## 7. 핵심 딱 정리

3일차 한 줄 요약: 누구를, 언제부터, 무엇을 셀지 정하고, 단계마다 행 수를 세고, 값을 먼저 확인한다.

### 7-1. 개념 8개

| # | 개념 | 한 줄 요약 |
| --- | --- | --- |
| 1 | CTE | `WITH 이름 AS (...)`로 중간 결과에 이름을 붙여 단계로 나눈다 |
| 2 | 코호트 | 누구를 + 기준일 + 사건 (+ 추적 기간)을 정해야 비율이 나온다 |
| 3 | LEFT JOIN | 왼쪽 행을 전부 남긴다. 사건 없는 사람도 분모에 남기려고 쓴다 |
| 4 | 행 수 변화 | JOIN은 행을 줄이고, 여러 행 테이블은 행을 늘린다. 환자당 1행으로 줄인 뒤 붙인다 |
| 5 | CASE WHEN | 위에서부터 처음 맞는 조건에서 멈춘다. 순서가 중요하고 ELSE가 없으면 NULL |
| 6 | 조건부 집계 | `AVG(CASE WHEN 조건 THEN 1 ELSE 0 END) * 100` = 비율(%) |
| 7 | NULL | 0이 아니라 "없음/모름". `IS NULL`로 묻고 `= NULL`은 쓰지 않는다 |
| 8 | 중도절단 | 끝까지 못 지켜본 사람. "사망 안 함"으로 세면 사망률이 낮게 나온다 |

### 7-2. 에러 없이 틀리는 함정 3가지

| 함정 | 증상 | 잡는 법 |
| --- | --- | --- |
| `JOIN` 사용 | 분모 감소 (8,436 → 3,293), 사망률 과대 | 단계마다 행 수 세기 |
| 문자 열을 숫자와 비교 | `'x'`가 0으로 바뀌어 그룹이 섞이고 4행이 3행이 됨 | 값별 인원을 먼저 세고 `IN ('0','1')`처럼 문자로 비교 |
| 중도절단을 생존으로 셈 | 최근 연도일수록 사망률이 낮게 나옴 | 분모에 누가 있는지, 사건을 놓친 사람이 있는지 묻기 |

### 7-3. 분석 전 체크리스트

- [ ] 각 테이블의 한 행이 무엇인지 확인했는가
- [ ] 쓸 열의 값을 `GROUP BY`로 먼저 세어 봤는가
- [ ] 코호트의 누구 / 기준일 / 사건 / 기간을 적었는가
- [ ] LEFT JOIN을 썼는가 (사건 없는 사람 보존)
- [ ] 여러 행 테이블은 환자당 1행으로 줄였는가
- [ ] 단계마다 행 수를 확인했는가
- [ ] NULL 판단에 `IS NULL`을 썼는가
- [ ] 숫자를 해석하기 전에 중도절단, 데이터 한계, 합성데이터 여부를 따져 봤는가
