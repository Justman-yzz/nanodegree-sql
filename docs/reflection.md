# LEARNING REFLECTION / SQL을 공부하며

이번 SQL 강의에서 가장 크게 배운 것은 **쿼리 실행 성공과 분석 결과의 타당성은 별개의 문제**라는 점이다. 처음에는 SQL 문법과 결과 창에 숫자가 나오는지에 집중했지만, 데이터가 어떻게 묶이고 연결되는지 이해하지 않으면 같은 데이터에서도 잘못된 결론을 낼 수 있다는 것을 확인했다.

1일차에는 `WHERE`로 범위를 지정하고 `JOIN`으로 상병코드에 한글 이름을 붙였다. 고혈압 코드 `I10`으로 검색했을 때 0행이 나왔지만 실제 청구 내역에는 `I109`가 들어 있었던 사례처럼, SQL 자체가 맞아도 데이터의 저장 형태를 살펴봐야 했다.

2일차에는 `GROUP BY`가 여러 행을 요약하는 반면 윈도우 함수는 원래 행을 유지하며 방문 순서와 간격을 계산한다는 차이를 배웠다. 특히 본인부담률을 계산할 때 단순히 개별 비율을 평균하는 것과 전체 부담금 합을 전체 진료비 합으로 나누는 것이 다르다는 점이 기억에 남았다.

3일차에는 코호트와 사망 기록을 연결하는 과정에서 `INNER JOIN`이 사망 기록이 없는 환자를 제거해 분모를 바꿀 수 있다는 점을 배웠다. 중도절단을 고려하지 않은 비율을 실제 생존율로 해석하면 안 된다는 사실도 중요했다.

기존에 배웠던 데이터 분석과 백엔드 개발 경험을 앞으로 더 발전시키려면, SQL로 결과를 빠르게 추출하는 것만큼 **분석 조건을 설명하고 결과를 검산하는 역량**이 필요하다고 느꼈다. AI가 SQL을 작성해 주더라도 쿼리의 의미를 이해하고 검증하는 역할은 직접 맡아야 한다는 생각으로 학습을 이어갈 계획이다.
