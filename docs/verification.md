# 실행 환경과 검증 안내

## 준비 환경

- MySQL 및 DBeaver (수업의 교육용 DB는 강의에서 배포됨)
- `kr_claims`와 `kr_lung_cancer` 데이터베이스
- 본 저장소는 **개인별 의료기록·합성데이터 전체·DB 접속정보를 포함하지 않음**

## 확인 순서

1. 수업에서 받은 교육용 DB를 별도로 설치하고 테이블이 존재하는지 확인한다.
2. `sql/practice/`의 기본 조회 SQL로 데이터 규모를 확인한다.
3. `sql/assignments/`의 재구성 SQL을 실행할 때는 주석에 적힌 조건과 결과의 불확실성을 확인한다.
4. `JOIN` 전후 행 수와 각 병기 그룹의 인원 합계를 비교한다.
5. 숫자가 맞아도 코호트 날짜·사망 기록 범위·중도절단 여부를 따져 해석한다.

## 교육용 데이터의 강의 노트 기준 검수값

```sql
SELECT COUNT(*) AS claim_rows FROM kr_claims.claim;                -- 노트 기준 38375
SELECT COUNT(*) AS cancer_patients FROM kr_lung_cancer.lung_pt_bsnf; -- 노트 기준 9897
```

강의에서 사용한 버전과 동일한 데이터베이스일 때만 수치 비교가 유효하다. 이 README에 있는 과제 2의 수치는 당시 전체 필터 조건이 미복원되어, 재구성 쿼리 결과와 동일하다고 보장할 수 없다.

## 수동 검수 체크

- [ ] 테이블이 실제로 존재하고 DB 스키마가 강의 노트와 같은가?
- [ ] 조건에 포함된 날짜·코드·입원/외래 구분이 문제 요구와 같은가?
- [ ] JOIN 뒤 합계와 고유 인원이 예상과 같은가?
- [ ] 원래 SQL과 재구성 SQL의 차이를 구분했는가?
- [ ] 결과 표에 합성데이터·중도절단 한계를 붙였는가?

> 이 저장소를 정리하는 작업 과정에서 실제 MySQL DB에 접근하지 않았기 때문에 `PASS` 등의 실행 결과를 새로 만들어 표기하지 않았다.
