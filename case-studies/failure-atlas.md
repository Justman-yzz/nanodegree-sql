# FAILURE ATLAS / 쿼리가 돌아갔는데 답이 틀리는 순간들

> 실제 SQL 학습 자료에 등장한 **5가지 오류·함정**을 다시 배열한 사례집. 성공적으로 실행된 결과와 타당한 해석은 별개다.

| 사례 | 겉으로 보이는 결과 | 실제 원인 | 검증 습관 |
|:--|:--|:--|:--|
| **01 / 0행** | 고혈압 검색 결과가 없다 | `I10`과 `I109`의 저장 코드 차이 | 코드 사전을 확인하고 실제 값의 분포를 살핀다 |
| **02 / ERROR 1055** | `GROUP BY` 실행 오류 | 그룹 기준이 아닌 열을 SELECT | 그룹 수준과 SELECT 수준을 일치시킨다 |
| **03 / ERROR 3593** | `WHERE`에서 `LAG`를 쓸 수 없다 | 윈도우 계산 이전에 필터하려고 했다 | CTE에서 계산한 뒤 밖에서 필터한다 |
| **04 / 분모 손실** | SQL은 통과했지만 사망률이 커졌다 | `LEFT JOIN` 대신 `INNER JOIN`으로 사건 없는 환자가 제외됨 | 코호트 8,436명 → 3,293명인지 검산한다 |
| **05 / 분류 오류** | 행 수 합이 맞아도 병기 그룹이 이상하다 | 문자 `'x'`를 숫자와 비교해 0으로 강제 변환 | 먼저 고유값별 건수를 세고 문자로 비교한다 |

## 하나 더 / 중도절단을 놓치면

3일차 실습에서는 1년 관찰 기간 이전에 기록이 끊긴 사람이 **4,098명(48.6%)**이었다. `사망 기록 없음`을 모두 `1년 생존 확인`으로 계산하면 실제로 관찰되지 않은 기간까지 결과에 포함시키게 된다.

**이것이 중요한 이유:** 쿼리가 맞는 것과 연구 질문에 답하는 것은 다르다. 먼저 대상, 기준일, 사건, 추적기간을 적어야 한다.

## 공개 전 점검

- [ ] 실습 자료가 가상/합성 데이터임을 표시했다.
- [ ] 환자 식별 데이터나 권한 없는 원본 데이터 파일을 공개하지 않았다.
- [ ] SELECT가 실패하지 않았다는 이유만으로 정답이라고 주장하지 않았다.
- [ ] 비교 지표의 분모·분자를 각각 설명했다.
- [ ] `JOIN` 전후 행 수와 NULL의 의미를 검증했다.
- [ ] 강의 노트의 예시 수치와 내 실제 실행·제출 결과를 구분했다.
